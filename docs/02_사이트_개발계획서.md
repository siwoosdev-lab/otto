# OttO 사이트 개발 계획서

> 본 문서는 OttO 서비스를 운영하기 위한 사이트·시스템 개발 계획입니다. 1인 또는 2인 개발 환경에서 빠르게 시작하고 점진적으로 확장하는 것을 전제로 합니다.

---

## 1. 시스템 전체 구조

### 1.1 전체 그림

```
┌─────────────────────────────────────────────────────────┐
│  [방문자]                                                │
│     ↓ 진단 신청                                          │
│  [랜딩 페이지] otto.kr                                   │
│     ↓ 폼 제출                                            │
│  [Tally / 자체 폼] → [Supabase DB] → [카톡/메일 알림]    │
│     ↓                                                    │
│  [내부 운영 대시보드] (대표용)                            │
│     ↓ 진단 후                                            │
│  [고객 대시보드] (Phase 2)                               │
│     ↓                                                    │
│  [자동화 모듈 백엔드] (Phase 3)                          │
│     ├─ n8n 워크플로우 엔진                               │
│     ├─ Claude / GPT API (텍스트 생성·요약)               │
│     ├─ 카카오 알림톡 / 비즈메시지                         │
│     ├─ 결제 (토스페이먼츠)                                │
│     └─ 고객 데이터 (각 고객 개별 Supabase 테넌트)        │
└─────────────────────────────────────────────────────────┘
```

### 1.2 핵심 설계 원칙

이 시스템은 다음 네 가지 원칙을 따릅니다.

먼저 **"가능한 한 만들지 않는다"** 입니다. 자체 개발 대신 검증된 SaaS·노코드 도구를 조립합니다. 1인이 1년 내 100팀을 운영하려면 자체 코드는 최소화해야 합니다.

두 번째는 **"고객 데이터는 고객 소유"** 입니다. 모든 고객 데이터는 사장님 명의의 클라우드 계정(구글 워크스페이스·노션 등)에 저장하고, OttO는 운영 권한만 받는 구조입니다. 이는 신뢰 확보뿐만 아니라 GDPR·개인정보보호법 리스크 회피에도 유리합니다.

세 번째는 **"모듈 단위로 적립"** 입니다. 한 고객을 위해 만든 자동화는 같은 패턴이라면 다른 고객에게도 즉시 재사용 가능하도록 모듈화합니다. 이게 OttO의 핵심 자산입니다.

네 번째는 **"점진적 확장"** 입니다. Phase 1에서는 랜딩 페이지와 폼만 있어도 서비스 제공이 가능합니다. 고객 수가 늘면 그때 대시보드·자동화 백엔드를 만듭니다. 처음부터 다 만들면 망합니다.

## 2. 기술 스택

### 2.1 Phase 1 — 검증 단계 (0~3개월, 비용 월 5만 원 이하)

| 영역 | 도구 | 용도 | 비용 |
|------|------|------|------|
| 랜딩 페이지 | HTML + Vercel | 정적 호스팅 | 무료 |
| 도메인 | otto.kr 또는 ottohq.com | 가비아·후이즈 | 연 1~2만 원 |
| 폼 수집 | Tally 또는 Typeform | 진단 신청 폼 | 무료~월 1.2만 원 |
| 데이터 저장 | Google Sheets + Supabase | 고객 정보 DB | 무료 |
| 알림 | 카카오 알림톡 | 고객 응대 | 건당 7~12원 |
| 메일 | Google Workspace | 비즈 메일 | 월 1만 원 |
| 일정 관리 | Cal.com 또는 Calendly | 진단 인터뷰 예약 | 무료~월 1.5만 원 |
| 결제 | 토스페이먼츠 또는 무통장 입금 | 셋업비·구독료 | 수수료 2~3% |
| 분석 | Plausible 또는 GA4 | 트래픽 분석 | 무료 |

### 2.2 Phase 2 — 본격 운영 (4~9개월, 비용 월 30만 원 이내)

| 영역 | 도구 | 용도 |
|------|------|------|
| 자동화 엔진 | **n8n** (자체 호스팅 또는 클라우드) | 워크플로우 빌딩 |
| AI API | **Anthropic Claude API**, OpenAI | 텍스트 생성·요약 |
| 백엔드·DB | **Supabase** | 인증·DB·서버리스 함수 |
| 고객 대시보드 | **Next.js** (Vercel 호스팅) | 고객용 웹앱 |
| 결제 자동화 | 토스페이먼츠 정기결제 | 월 구독료 자동 청구 |
| 카톡 챗봇 | 카카오 i 오픈빌더 또는 ManyChat | 자동 응대 |
| 모니터링 | Sentry + UptimeRobot | 에러·가동률 모니터링 |
| 고객 응대 | 채널톡 또는 카카오 채널 | CS 채널 |

### 2.3 Phase 3 — 확장 (10개월~, 비용 월 100만 원 이내)

| 영역 | 도구 |
|------|------|
| 모듈 마켓플레이스 | 자체 개발 (Next.js + Supabase) |
| 다지점 통합 대시보드 | Retool 또는 자체 개발 |
| API 게이트웨이 | Cloudflare Workers |
| 데이터 분석 | Metabase + Postgres |

### 2.4 왜 이 스택인가
**Vercel + Next.js + Supabase**는 한국에서도 가장 빠르게 출시할 수 있고, 무료 티어가 넉넉하며, 1인 개발자가 운영하기에 가장 부담이 적습니다. **n8n**은 자동화 엔진의 사실상 표준이며 자체 호스팅 가능해 단가가 통제됩니다. **Claude API**는 한국어 처리 품질과 긴 문맥 처리에서 강점이 있어 진단 리포트·고객 응대 자동화에 적합합니다.

## 3. 사이트 구조

### 3.1 페이지 구조

```
/ (홈/랜딩)
├── /apply           무료 진단 신청 폼
├── /pricing         요금 안내
├── /industries      업종별 자동화 사례 (14개)
│   └── /industries/[slug]   업종별 상세 페이지
├── /modules         자동화 모듈 카탈로그
├── /case-studies    고객 사례 (시범 운영 후 추가)
├── /blog            콘텐츠 마케팅용 블로그
├── /about           회사 소개·창업 스토리
├── /faq             자주 묻는 질문
├── /privacy         개인정보 처리방침
├── /terms           이용약관
│
├── /admin           내부 운영 대시보드 (관리자 전용)
│   ├── /admin/leads        진단 신청 관리
│   ├── /admin/customers    고객 관리
│   ├── /admin/modules      모듈 라이브러리
│   └── /admin/analytics    매출·MRR 대시보드
│
└── /app             고객 대시보드 (Phase 2)
    ├── /app/dashboard      자동화 현황
    ├── /app/modules        활성 모듈
    ├── /app/savings        절감 효과 리포트
    └── /app/billing        결제·청구
```

### 3.2 Phase별 우선순위

**Phase 1에서 만들 것**: `/`, `/apply`, `/pricing`, `/faq`, `/privacy`, `/terms` 만 만듭니다. 나머지는 Notion 또는 임시 페이지로 대체.

**Phase 2에서 추가**: `/industries/*`, `/case-studies`, `/blog`, `/admin/*`.

**Phase 3에서 추가**: `/modules`, `/app/*` (고객 대시보드).

## 4. 데이터베이스 설계 (Supabase)

### 4.1 핵심 테이블

```sql
-- 진단 신청 (leads)
leads {
  id: uuid (PK)
  name: text
  phone: text
  industry: text
  business_size: enum (1인, 5명이하, 20명이하, 그 이상)
  pain_points: text
  source: text (어떤 채널에서 왔는지)
  status: enum (신규, 진단완료, 셋업중, 활성, 이탈)
  created_at: timestamp
  diagnosed_at: timestamp
  notes: text
}

-- 고객 (customers)
customers {
  id: uuid (PK)
  lead_id: uuid (FK)
  business_name: text
  contract_started_at: timestamp
  plan: enum (Starter, Pro, Business)
  monthly_fee: integer
  setup_fee_paid: boolean
  status: enum (활성, 일시정지, 해지)
  next_billing_date: date
  founding_member: boolean
}

-- 자동화 모듈 카탈로그 (modules)
modules {
  id: uuid (PK)
  name: text
  category: enum (응대, 알림, 문서, 마케팅, 데이터, 운영)
  industry_tags: text[]
  description: text
  estimated_setup_time: interval
  estimated_savings_per_week: interval
  config_schema: jsonb
  workflow_template_url: text
  created_at: timestamp
}

-- 고객별 활성 모듈 (customer_modules)
customer_modules {
  id: uuid (PK)
  customer_id: uuid (FK)
  module_id: uuid (FK)
  config: jsonb (고객별 설정값)
  status: enum (활성, 일시정지, 오류)
  installed_at: timestamp
  last_run_at: timestamp
  total_runs: integer
  total_saved_seconds: integer
}

-- 자동화 실행 로그 (executions)
executions {
  id: uuid (PK)
  customer_module_id: uuid (FK)
  executed_at: timestamp
  status: enum (성공, 실패, 부분성공)
  duration_ms: integer
  saved_seconds: integer
  output_summary: text
  error_message: text
}
```

### 4.2 분석 뷰

대시보드에서 자주 쓸 집계는 매번 계산하지 않고 Supabase의 materialized view로 만들어둡니다. 예: 고객별 월간 절감 시간, 모듈별 평균 성공률, 채널별 전환율 등.

## 5. 핵심 워크플로우

### 5.1 진단 신청 → 첫 상담까지

```
1. 방문자가 /apply 폼 제출
2. Tally → Supabase leads 테이블 자동 입력
3. 대표 카톡으로 새 신청 알림 발송 (n8n)
4. 24시간 내 첫 응답 (대표 또는 자동 응답)
5. Cal.com 링크로 30분 진단 일정 예약
6. 진단 24시간 전 자동 리마인더 카톡
7. 진단 완료 후 leads.status = "진단완료"
8. AI가 인터뷰 녹취록 → 진단 리포트 PDF 자동 생성
9. 고객에게 리포트 + 견적 카톡 발송
```

### 5.2 셋업 진행

```
1. 견적 동의 시 leads → customers로 전환
2. 셋업비 청구 (토스페이먼츠 또는 계좌 이체)
3. 입금 확인 후 customer_modules에 설치 예정 모듈 등록
4. n8n 템플릿 복제 → 고객 설정값 주입
5. 테스트 실행 → 정상 동작 확인
6. 직원 1회 교육 (화상 30분)
7. customer_modules.status = "활성"
8. 다음 결제일에 첫 월 구독료 자동 청구 시작
```

### 5.3 운영 모니터링

```
- 매일 새벽: 모든 customer_modules의 상태 점검 (n8n)
- 오류 발생 시 대표 카톡 즉시 알림
- 매주 월요일: 고객별 주간 절감 효과 리포트 자동 생성·발송
- 매월 말: MRR·이탈율·NPS 자동 집계
```

## 6. 보안과 컴플라이언스

### 6.1 데이터 처리 원칙
모든 고객 데이터는 **고객 소유 클라우드**에 저장합니다. 예를 들어 학원의 학생 명단은 학원장 명의의 구글 시트나 노션에 저장하고, OttO는 OAuth 권한만 받습니다. 계약 종료 시 권한이 즉시 회수되며, OttO 서버에 데이터가 남지 않습니다.

### 6.2 개인정보보호법 대응
- 진단 신청 폼에 개인정보 수집·이용 동의 명시
- 처리 위탁 계약서를 모든 고객과 체결
- 개인정보처리방침을 사이트에 공개
- 6개월 이상 미사용 leads는 자동 폐기

### 6.3 인증·접근 제어
- 내부 운영 대시보드: Supabase Auth + 2FA 필수
- 고객 대시보드: 카카오 로그인 또는 이메일 매직 링크
- API 키는 모두 환경 변수로 관리, GitHub에 커밋 금지

### 6.4 백업
- Supabase 자동 일일 백업
- 핵심 모듈 워크플로우는 GitHub에 버전 관리
- 매주 1회 수동 스냅샷 별도 보관

## 7. 개발 우선순위 (스프린트 계획)

### 스프린트 1 (Week 1~2) — 랜딩 + 신청
- 도메인 등록, Vercel 배포 환경 셋업
- 랜딩 페이지 (이미 있는 HTML 활용)
- Tally로 진단 신청 폼 제작 → Supabase 연동
- Google Workspace 비즈 메일 셋업
- 카카오 채널 개설 + 알림톡 비즈 등록 신청

### 스프린트 2 (Week 3~4) — 운영 도구
- 노션 또는 Supabase에 leads 관리 대시보드
- Cal.com 진단 예약 시스템 연동
- AI 기반 진단 리포트 PDF 자동 생성 워크플로우 (n8n)
- 카톡 알림 자동화 (새 신청, 일정 리마인더)

### 스프린트 3 (Week 5~6) — 첫 고객 대응
- 셋업 SOP 문서화 (실제 첫 고객으로 검증)
- 모듈 라이브러리 첫 5개 (카톡 챗봇, 알림 자동화, 청구서, 리뷰 응답, 콘텐츠 생성)
- 결제 시스템 셋업 (토스페이먼츠)
- 운영 모니터링 알림 셋업

### 스프린트 4~6 (Week 7~12) — 확장 준비
- /industries/[slug] 동적 페이지 (SEO용)
- 사례 콘텐츠 페이지
- 추천인 코드 시스템
- 첫 광고 캠페인 LP

## 8. 비용 추정 (월 단위)

### Phase 1 (0~3개월)
- 도메인·호스팅·메일: **월 1.5만 원**
- 폼·일정 도구: **월 1만 원**
- AI API (저사용): **월 5만 원**
- 카톡 알림톡: **월 2만 원**
- **합계: 약 월 10만 원**

### Phase 2 (4~9개월, 고객 30팀 가정)
- 위 항목 + 자동화 엔진(n8n) + 모니터링: **월 30만 원**
- AI API (적정 사용): **월 50만 원**
- **합계: 약 월 80만 원**

### Phase 3 (10개월~, 고객 100팀 가정)
- 위 항목 + 백엔드 인프라 확장: **월 150만 원 이내**
- AI API: **월 200만 원** (사용량 기반 추가 과금으로 일부 회수)
- **합계: 약 월 350만 원**

이 시점 MRR 2,500만 원 가정 시 인프라 비용은 매출의 14% 수준으로, 일반적인 SaaS 인프라 비용 비중(20% 이내)과 비교해 건전합니다.

## 9. 모니터링·분석 지표

대시보드(`/admin/analytics`)에서 매일 추적할 지표는 다음과 같습니다.

**전환 깔때기**: 방문자 → 신청 → 진단 → 견적 → 계약 → 셋업 완료 → 첫 결제. 각 단계 전환율을 일/주 단위로 기록.

**MRR과 이탈율**: 월 반복 매출, Net New MRR, 월간 이탈율(Churn rate), 추천 유입 비율.

**고객 건강도**: 모듈 활성 비율, 주간 자동화 실행 횟수, 절감 시간 추이, NPS.

**비용**: AI API 사용량, 인프라 비용, CAC, LTV/CAC.

**제품 품질**: 자동화 모듈 성공률, 평균 셋업 기간, CS 응답 시간.
